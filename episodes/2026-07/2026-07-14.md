# 2026-07-14 — 用边界纪律讲清 HAKO 与妙搭

## 摘要

今天完成了一轮 HAKO 源码、架构文档、Windows E2E、简历与飞书妙搭公开资料的交叉审阅，并整理成面试手册。重点不是把系统包装得更大，而是把真实能力、部署成熟度、已知风险和只能类比不能断言的部分分开。

## 重要事件

- 将 HAKO 定位为面向 AI Agent 的分布式远程执行平台：MCP Client、gRPC Server 控制面、Worker 双向长连接与 Action/TaskManager。
- 明确它目前不是完整 Agent Planner、成熟多租户云沙箱，也不能被描述成妙搭内部架构的复刻。
- 复审出五项关键风险：重复注册可能误注销有效连接、Worker 断连后 pending Future 只能等超时、同一 gRPC 流潜在多协程写、资源级授权闭环不足、下载流鉴权与内容完整性校验不足。
- Windows E2E 证明主链路可用，但 `grep count` 和 `context` 仍有行为偏差，因此不能宣称全面生产验证。
- 对飞书妙搭只依据官方公开产品能力做能力层类比，不推断其内部通信协议、隔离技术或 Worker 实现。
- 新增 `knowledge/technical/hako-miaoda-interview-playbook.md`，包含讲述版本、架构时序、追问、边界、简历串联和速记卡。

## 沉淀

- 面试表达不是把系统说满，而是建立证据梯度：源码能证明什么、测试能证明什么、部署还缺什么、外部产品只能类比到什么层。
- 系统边界说得越清楚，可信度越高；承认未完成项不是削弱项目，而是证明真正理解它。
