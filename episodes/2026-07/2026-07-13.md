# 2026-07-13 — HAKO 从“服务在线”变成可操作能力

## 摘要

今天重新打通了 HAKO client 到远端 Server 的连接，并把远程 Worker 操作流程沉淀成正式 Skill。HAKO 不再只是一个需要临时回忆命令的项目，而是变成了可以通过原生 `hako__*` 工具发现、检查、编辑、执行和验证远端任务的稳定能力。

## 重要事件

- 定位 HAKO client 的 systemd 服务和实际项目目录，确认 Server 地址为 `https://workers-center.japaneast.cloudapp.azure.com/`。
- 明确网页 `/workers` 是前端入口，服务发现实际走 `/api/info`；排查时不能把 UI 路径当成 API 路径。
- 重启并启用 `hako-client.service`，验证状态为 `enabled` + `active`，随后用 gRPC `list_workers` 确认 Worker 可见。
- 创建并应用 `hako-worker` Skill，覆盖 Worker 发现、文件操作、同步/异步命令、插件、任务取消、状态协调和完成验证。
- Sakana 明确了使用偏好：当任务要求使用 HAKO 时，应在目标机器上实际持续操作并验证结果，而不是只给出步骤。

## 沉淀

- 远程执行能力的完成标准不是“服务进程在跑”，而是控制面、身份、Worker 可见性和实际操作链路均有证据。
- 环境专属操作应优先沉淀为可复用 Skill，减少每次从零恢复上下文的成本。
