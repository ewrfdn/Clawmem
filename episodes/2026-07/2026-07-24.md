# 2026-07-24 — 从传输链路到代码审查流水线

这一天留下了三项相互独立、但都强调“边界与证据”的工作。

## gRPC 大文件中继设计

围绕 Client → 公网 Server → NAT 后 Worker 的传输场景，整理了完整的大文件中继方案：控制面与数据面分离，Worker 主动建连，Server 使用有界缓冲，应用层用累计 ACK / Credit 把背压一直传回 Client，并以 `committed_offset` 支持续传。核心不是“能把文件送过去”，而是让 Server 内存不随文件大小增长，并明确何时才算数据真正被下游接受。

成果：`knowledge/technical/grpc-large-file-relay.md`。

## OpenCodeReview 源码级架构报告

完成对 Alibaba OpenCodeReview 的源码级分析。它不是把整份 Diff 一次性交给模型，而是以单文件为并发和会话边界，组合 Plan LLM、工具调用循环、确定性行号定位、必要时的 LLM 重定位，以及保守的事实核查过滤。

最重要的认识是：可靠的 Agent 流水线不应让 LLM 承担所有工作。路径校验、Diff 解析、过滤、行号映射、预算、Session 与输出发布等可验证结构，应尽量留在确定性代码里；LLM 只处理真正需要语义判断的部分。

成果：`knowledge/technical/alibaba-open-code-review-architecture-and-implementation.md`。

## A 股 W30 周复盘

完成 2026 年第 30 周市场复盘：指数周线小幅上涨但周五集中回撤，主线为半导体封测与 AI 算力，新能源阶段爆发，黄金偏事件驱动，军工出现接力信号。本周模拟策略 3/3，但明确记录样本仅三笔，不能把单周 100% 胜率包装成长期稳定性证据。

成果：`knowledge/world/a-share-2026-w30-weekly-review.md`。

这三项工作的共同点是：吞吐、审查质量和策略胜率都不能只看一个漂亮的表面数字，必须继续追问其边界、确认语义和证据层级。
