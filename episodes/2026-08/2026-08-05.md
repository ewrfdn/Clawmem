# 2026-08-05 — NUC 上的完整 OpenClaw 节点

今天把 NUC 从一台在线 Worker 推进成了一个可独立运行 OpenClaw 和本地数据服务的节点。

OpenClaw 部署在单节点 Kubernetes 中：Pod `1/1 Running`、零重启，10Gi PV/PVC 已绑定，Service 保持 ClusterIP，Gateway 只监听 loopback，`/healthz` 返回 200，配置校验无 warning。DeepSeek 不是内置开关，而是独立官方 provider 插件；我把插件安装到持久化 OpenClaw home，显式加入 allowlist，并从 Kubernetes Secret 注入 API key。随后真实调用 `deepseek/deepseek-v4-flash`，响应为 HTTP 200 和准确的 `pong`，provider/model 元数据确认没有走 fallback。

晚些时候又完成 OpenClaw 原生 GitHub Copilot device login，把 auth profile 保存在持久化 agent auth store，并将 `deepseek` 与 `github-copilot` 一起列入插件 allowlist。`github-copilot/gpt-5.6-sol` 的真实调用同样返回 HTTP 200 和 `pong`，至此两条模型链路都能独立工作。

数据层用 Docker Compose 部署 PostgreSQL 17.6 和 Redis 7.4.2。两者只绑定 `127.0.0.1`、使用持久化 volume、设置 `unless-stopped` 并保持 healthy；PostgreSQL 通过认证 TCP 完成 create/insert/select/drop，Redis 通过认证完成 PING/SET/GET/DEL，未认证请求正确返回 `NOAUTH`。凭据保存在权限收紧的 env 文件中；聊天里出现过的 DeepSeek key 已被视为泄露并提醒轮换。

这次最重要的不是“所有状态都绿了”，而是把每个绿色状态的证明范围说清楚：Pod Running 不证明模型能调用，HTTP 200 不证明没有 fallback，容器 healthy 不证明认证和 CRUD 正常。可靠部署是一条从配置、存储、网络、权限到真实业务调用的证据链。
