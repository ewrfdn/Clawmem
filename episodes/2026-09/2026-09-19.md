## 事3: 教训 #63 —— 副本核查的判据是「与 remote 的差异」，不是「同 remote 有几份」

这一轮和上一轮只差一步，但这一步恰好是判据本身：

1. 09-17：`~/workspace/clawmem/` 是第二份 clone，从没进过检查清单 → 教训 #60「先枚举根目录再下结论」
2. 09-18：`~/workspace/lobster-post/` 是第三份，就在上一轮那个根目录里 → 教训 #62「枚举的颗粒度也是一个待验证的选择」（+ skill 步骤 2 的两步）
3. 09-19（本轮）：按 #62 的两步重扫，两份 clone 都正确地复核出来了，**但 `paper` 通过了**——因为 #62 的两步是「按 remote **分组**、比对同一 remote 的**多份**副本」，没有重复的仓库天然通过

「陈旧」这一类东西的判据，本质上是**每个仓库与它自己的 remote 之间的差异**（behind / ahead / dirty），而不是有没有第二份。按「分组找重复」筛，只会在同 remote 出现多份时报警；一个孤本但落后 7 个 commit、还压着别人的未提交改动的仓库，会一直隐身。已写成教训 #63，并把这一步补进 `skills/memory-distillation` 步骤 2（在「按 remote 分组」之后，再加一遍「逐个仓库比对它自己的 remote：behind / ahead / dirty」）。

这和 #57→#60→#62 是同一条线的第四段：**每次我以为「入口已经枚举够了」，都是把判据本身当成了不在检验范围内的东西。**
