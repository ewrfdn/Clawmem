### 文生图 `qwen_image_2.1_t2i_test.json`
- 节点 `TextEncodeQwenImage21`（`comfy_extras/nodes_qwen.py`）原生支持：txt2img 时同时输出 pos/neg conditioning + 空 latent
- 官方 t2i 模板仍用 `EmptyLatentImage` 喂 KSampler —— `fix_empty_latent_channels` 会把全零 4ch/8× latent 自动转成 64ch/16×
- latent format: **64 通道 / 空间 16× 下采样**（新 VAE）
- 官方参数: KSampler 25 steps / cfg 1 / euler / simple；CLIPLoader type=`qwen_image`；模型原生 2K（2048²）
- 实测: 1024×1024、25 步、seed 42、**34.7s** → `Qwen_Image_2.1_test_00001_.png`，色彩分析符合雨夜霓虹场景（非坏图）
- 坑: `TextEncodeQwenImage21.images` 是 **autogrow（min=0）**，API 格式必须显式传 `"images": []`，否则验证直接报缺输入

### 图生图 `qwen_image_2.1_i2i_test.json`（同日第二轮）
这一轮 **comfyui MCP runtime 挂了**（bundle-mcp runtime disposed），全程改直连 HAKO API（curl），无阻塞。

- 官方编辑模板来源: `Comfy-Org/workflow_templates` 仓库（顺带否掉三条路：templates.comfy.org 不存在、npm wheel 是空壳 meta-package、ComfyUI_examples 只有旧的 2509 编辑模型）
- 结构关键差异:
  1. **latent 不接 `EmptyLatentImage`**，直接接 `TextEncodeQwenImage21` 的第三个输出（按第一张参考图尺寸生成空 latent）
  2. **VAE 必须连到 `TextEncodeQwenImage21`** —— 否则参考图只进 vision tower、不进 VAE latents，就不是真编辑
  3. `LoadImage` → 编码节点的 `image_1`（多参考图接 image_2…image_16）
  4. 采样参数不变: 25 步 / cfg 1 / euler / simple / **denoise 1.0**（参考图在 conditioning 里）
  5. 官方另有 `QwenImage21Cache`（KV cache offload），GB10 显存富裕未加
- autogrow 带图的写法（本轮实证）:
  - API 格式: `"images": {"image_1": ["5", 0]}`（嵌套 dict，键名 `image_1`..`image_16`）
  - UI 格式: inputs 数组里 `{"name": "images.image_1", "shape": 7, "type": "IMAGE", "link": 9}`
- 远程 API 的三个信封细节:
  - userdata 读取/保存都要 **encoded slash**（`workflows%2Fxxx.json`），裸斜杠 404；POST body 为原始文件字节
  - `/prompt` 提交必须 `{"prompt": wf, "client_id": ...}` 信封，裸工作流报 `no_prompt`
- 实测: 雨夜霓虹招牌 →「改正午晴天」，**luma 21.8 → 124.5**，色调从品红（39.9/14.6/39.9）变蓝天（109.8/128/147.3），编辑确实生效
- 本机无 PIL，色彩分析用 **Node 手写 PNG 解码器**（zlib + unfilter）替代
