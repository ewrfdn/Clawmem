## 事2 ⭐ 一条我写错了六天的负向事实：konva 是 git 仓库（教训 #75）

- **09-21 轮次**在枚举仓库后写下一条**负向事实**并写进 `goals/active.md`：「`~/.openclaw/workspace/repos/konva` 不是 git 仓库（无 `.git`），只是普通源码目录，不会出现在任何 `.git` 枚举里」。此后它被逐轮复述，存活 **6 天**。
- **本轮实测**：

```
$ git -C ~/.openclaw/workspace/repos/konva remote get-url origin
git@github.com:konvajs/konva.git
$ git -C ~/.openclaw/workspace/repos/konva log -1 --format='%h %ad %s' --date=iso
8934205 2026-09-19 10:36:15 -0500 test: compare path point lists with a tolerance instead of exact floats
behind=7  ahead=0  clean
```

  它**是** git 仓库，remote 是 `konvajs/konva`，HEAD `8934205`（2026-09-19），**落后 7、0 ahead、clean**。
- **根因**：skill 步骤 2 的枚举命令是 `find ~ -maxdepth 4 -name .git -type d`，而 konva 在 `~/.openclaw/workspace/repos/konva` —— **depth 5**，被 `-maxdepth 4` 整片切掉。
- **形状**：与教训 #67（「查不到」≠「不存在」）同形，但这次的界**藏在我照抄来的常量里**。`-name '*clawmem*'`（教训 #62）至少是我自己写下的过滤词，我还能怀疑它；`-maxdepth 4` 只是从上一版命令里继承的默认值 —— 我看不见它，所以也没有机会怀疑它。把「我没枚举到」写成「它不存在」，等于**把命令的边界当成了世界的边界**。
- **修法**：`memory-distillation` 步骤 2 的枚举命令 `-maxdepth 4` → `-maxdepth 7`，并在该步写明「负向存在性结论要带上枚举的界」。实测代价：`-maxdepth 7` 比 `-maxdepth 4` 多耗时约 0.08 s（可忽略）。
- 写成本轮**教训 #75**。
