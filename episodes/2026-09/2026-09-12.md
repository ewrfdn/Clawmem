## 事2: Widget sandbox host is unavailable（本机侧修复完成，端到端未验证）

### 现象
Control UI 聊天里的 widget 显示 `Widget sandbox host is unavailable.`

### 诊断链路
1. 前端报错字符串 `sandboxUnavailable` 定位到 `dist/control-ui/assets/control-ui-core-BHfdLkse.js`
2. `docs/web/dashboard-architecture.md`：scripts 模式下 inline/board widget 都强制走 dedicated-origin sandbox proxy
3. `docs/cli/mcp.md`：`mcp.apps.enabled` 时网关在 port+1（18790）起沙箱监听器
4. 本机配置里**没有 `mcp.apps`** → 宿主从未启动。18001 被占用且返回 404，不是沙箱监听器（排除误判）
5. 补证：同二进制里 sandboxPort 默认 = base + 1 = 18001，与本任务提示上下文一致；旁边还有独立的 go 服务（AI-Infra-Guard）在跑 trpc 心跳，说明 18001 的占用者另有其人

### 已做（本机侧全部完成）
1. 配置：`mcp.apps.enabled=true`、`sandboxPort=18790`、`sandboxOrigin=https://hako.japaneast.cloudapp.azure.com:18443`
   —— 用同域名换端口（18443）制造独立 origin，复用现有 Let's Encrypt 证书，不动 DNS
2. nginx：`sites-enabled/hako` 追加 18443 ssl server 块 → `proxy 127.0.0.1:18790`
   —— **available 与 enabled 是两个独立文件（非软链），只改一个无效**；本机两个文件内容本来就不一致（enabled 多了 comfyui/vmess-ws 等 location）
3. nginx reload 成功，18443 已监听
4. 备份：`openclaw.json.bak-*`、nginx `hako.bak-*`
